# 职得 WORTH

> 能力职得其所，未来值得期待。

职得（WORTH）是面向学生、企业与高校的三方信息适配平台，聚焦岗位需求与个人能力之间的信息差。平台以真实岗位技能要求为参照，帮助学生了解目标岗位、识别能力差距，并逐步形成可执行的成长路径；同时为企业和高校提供更结构化的人才需求与培养反馈。

## 项目目标

平台规划围绕“岗位需求—能力认知—差距补齐—成长反馈”形成闭环：

1. 汇集并整理岗位信息，逐步建设岗位技能库。
2. 通过多维能力测评形成个人能力画像。
3. 对照目标岗位要求分析技能差距与补齐优先级。
4. 将差距转化为分阶段、以实践任务为核心的个性化学习路径。
5. 记录测评与任务进度，以能力成长地图持续呈现变化，并反馈至后续测评。

## 当前项目结构

- `index.html`：品牌首页与职位浏览入口。
- `worth/`：Spring Boot、Spring Data JPA 与 MySQL 后端，提供职位相关接口及数据导入能力。
- `zhide-spider/`：职位数据采集脚本；采集结果不纳入仓库。

当前代码主要处于 MVP 阶段。首页、职位浏览与后端职位接口是现有实现；注册登录、能力测评、差距分析、个性化学习路径和成长地图属于后续建设方向，不应视为已上线功能。账号认证和岗位访问控制目前仍是前端演示状态。

## 技术路线

采用前后端分离的模块化单体架构，以 REST API 逐步连接现有 Web 页面和后端；先保持单体部署，不提前拆分微服务。当前实现以 HTML、CSS、JavaScript、Spring Boot、Spring Data JPA 和 MySQL 为基础。技术路线规划进一步包括：

- 后端：Java 21、Spring Boot 4.x、Maven、Spring Web、Spring Validation、Spring Data JPA。
- 数据库：MySQL 8.x，统一使用 `utf8mb4`；数据库结构计划使用 Flyway 进行版本化迁移。
- 前端：先复用现有页面；功能稳定后，再按需要迁移到 Vue 3 与 Vite。
- 数据接入：将已有 CSV/JSON 职位数据经字段映射、校验、标准化和去重后批量导入，不把爬取过程放入用户请求链路。
- 质量保障：为核心服务与接口补充自动化测试，覆盖分页筛选、数据导入和权限边界。

上述路线是项目规划，技术组件会随阶段逐步落地；请以代码和各阶段交付为准，不将规划描述理解为当前已完成能力。

## 开发规划

1. **职位数据与浏览**：完善数据库迁移、已有数据导入、职位列表/详情、关键词与条件筛选及分页。
2. **用户基础能力**：实现注册登录、个人资料、收藏与角色权限，并验证用户数据隔离。
3. **能力画像与差距分析**：建设技能题库、测评记录和可解释的规则化差距分析。
4. **学习与成长闭环**：建设实践任务、学习进度和成长地图，串联“职位—测评—差距—学习—成长”。

每一阶段以可演示、可复测为验收标准；阶段时间根据实际开发进度调整。

## 本地运行

后端需要 Java 17 和 MySQL。先创建名为 `worth` 的数据库，再将 `worth/src/main/resources/application-example.properties` 复制为同目录下的 `application.properties`，并通过环境变量设置数据库账号密码；如需启用管理接口，再设置 `WORTH_ADMIN_KEY`。不要将真实凭据提交到仓库。

在 `worth` 目录运行：

```powershell
./mvnw.cmd spring-boot:run
```

- 首页：<http://localhost:8080/>
- 职位接口：<http://localhost:8080/api/v1/jobs>

爬虫依赖见 `zhide-spider/requirements.txt`。执行采集前请遵守数据来源网站的服务条款、robots 协议和授权范围；不要绕过访问控制或反爬机制。

## 数据与安全说明

仓库不包含本地数据库密码、环境变量、职位采集结果、个人文档或构建产物。用户数据应遵循最小必要原则；日志不得记录密码、令牌等敏感信息。职位数据应保留必要来源与采集时间，并按来源要求管理、更新或删除。
